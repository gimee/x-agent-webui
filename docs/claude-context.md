# Claude host-managed context (v0.5.0)

## Scope

The Linux **global Studio chat** path enables this wrapper for any Claude 5+ `opus`/`sonnet`/`fable` model id (`claude-opus-5-5`, a future `claude-opus-5-6`, `claude-opus-6`, ...; launched with `[1m]`) or an explicitly selected `[1m]` model. The rule is a capability rule, not a name list, so a new model id needs no release. `<WebUI home>/coding-agent/claude-context/models.json` (`{"include":[...],"exclude":[...]}`) adds a proxy alias or backs a model out; a malformed file is ignored. An empty `DISABLED` file in the same directory returns every launch to native immediately; delete it to re-enable. Neither needs a rebuild. Other platforms/models, scoped launches, inherited native forks and unparsed project/enterprise settings keep their existing native behavior. It does not rewrite the user's Claude settings, API credentials, binary, or native transcript. Terminal launches outside Studio remain native.

Automatic compaction is checked at a **safe user-turn boundary** once the existing native context reaches the configured trigger (default 400,000 tokens; v0.5.1: see [Compression settings](#compression-settings-v051)). It is not an interruption of an active tool call. A native auto-compact window (default 600,000 tokens, ~567K after native buffers; v0.5.1: `min(1M, max(600K, trigger + 200K))`) is the backstop for a single unusually long agent loop; a private-overlay `PreCompact` hook (`bin/claude-context/precompact-hook.mjs`) gives that native summary the same memory-first instructions (every user message verbatim, requirement status, exact identifiers, transcript path). The hook always exits 0 and never blocks compaction. Ordinary low-context turns use fresh native message usage without starting a second CLI process.

## Memory-first retention

Users lost context after short summaries, so the retained successor context is filled in priority order:

1. **Every genuine user message, verbatim**, carried forward across generations in `checkpoint.ledger` (never re-summarized). Extracted from the whole native file, so messages before earlier native compactions are recovered; tool results, task notifications, native summaries, meta prompts and this wrapper's own prefix are excluded. Budget ~24K tokens; if exceeded only the longest messages are shortened to head/tail, and in the extreme the opening task and newest messages are kept.
2. **Detailed sectioned summary**. v0.5.1: written by the WebUI auxiliary compression model (「模型 → 辅助模型 → 压缩」, the same summarizer and prompts as Hermes chats; see [Auxiliary summary](#auxiliary-summary-v051)); when that is unavailable, fails, times out or is invalid, a read-only Claude fork writes it in the same turn (goals, constraints, decisions with reasons, completed work with evidence, failed approaches, current work/next step, open questions; ~6-12K words).
3. **Transcript archive index**: each source native transcript is copied to `<scope>/archive/<native>.jsonl` (0600, SHA-256 verified) because native files can be cleaned up; the successor is told to Grep/Read these when a detail is missing.
4. **Most recent raw history** fills the remainder; tool inputs/results over 8KB keep head/tail so the window spans more turns. v0.5.1: at least the newest `protect_last_n` records (default 20) stay verbatim, whole tool exchanges, growing the budget up to `protectLimit` = max(target, trigger × 0.5) (200K by default), never past the hard limit; a larger text record is excerpted as before.

v0.5.1 also quotes the conversation's **opening records** (`protect_first_n`, default 3): the earliest raw records of generation 0 in file order (user/assistant rows, not sidechain, meta or native compaction summaries, so a native compaction boundary cannot hide the real opening), taken at the first compaction (from the private gen-0 archive for an older checkpoint), stored in `checkpoint.firstRecords` and carried under a labelled "OPENING RECORDS … historical reference" block inside section [3/4] of every later compaction (not repeated when they are also recent).

The target (default approximately 80,000 tokens = 20% of the 400K trigger; v0.5.1: `min(1M × target_ratio, trigger × 0.8)`) is a **floor** with no safety reserve: when fixed context + ledger + summary exceed it, the budget grows (at least 8K of recent history) instead of dropping memory or failing the turn; only the hard limit fails (200K until v0.5.0; v0.5.1: trigger × 0.9, 360K by default). v0.5.1: before any summary is requested the wrapper checks the fixed part (ledger, archive index, opening records, current input, non-message context) plus the summary budget against the hard limit. When that, or after the summary the whole successor, does not fit, a **threshold** compaction prints `failed` / `over_budget` and is skipped for this turn: the native session continues with the user's input and nothing is recorded (a written archive copy is harmless; ledger, archive list, bootstrap, retention and summary stay as they were), so a low threshold with a long paste cannot lock the conversation. A manual `/compact` still fails, as an explicit request. The selector uses the native Messages count to calibrate a byte estimate, capped at 0.75 tokens/byte (native Messages also counts ~24K tokens of hidden injections — skill/agent listings, instructions — which on a small chat inflated the ratio ~70x and failed a manual `/compact` against the hard limit; fixed in v0.5.0); it is **not an exact Claude tokenizer or a hard guarantee**. A large indivisible tool exchange may yield less retained text. Do not pad with synthetic content to make a target appear exact.

## Flow and ownership

1. Preserve the original Studio session and its message history.
2. Read the active parent chain from the exact native session under `CLAUDE_CONFIG_DIR/projects`; reject mismatched scope, symlinks, cycles, broken parents and incomplete tool pairs. The workspace check binds the session **origin** (its first non-sidechain row with a `cwd`) to the wrapper's workspace; a session started elsewhere is rejected (`Native workspace mismatch`, exit 75). Later rows record Claude's per-turn shell directory (a Bash `cd` outside the workspace that Claude resets, an entered worktree) and need neither match nor still exist (v0.5.0; earlier releases failed such sessions with exit 75).
3. Generate the summary: v0.5.1 first asks the WebUI auxiliary summary endpoint; otherwise (or with `NATIVE_SUMMARY`) through `--resume <source> --fork-session --no-session-persistence`, with model tools and MCP disabled, verifying the source transcript hash remains unchanged.
   Before the summary the wrapper prints `{"type":"system","subtype":"host_compaction","status":"started","pre_tokens":N}` and, once retention is selected (before the successor starts), `status:"completed"` with `post_tokens` (the estimate) and v0.5.1 `summarizer:"aux"|"claude"` (plus `reason`, the short fallback code, when Claude wrote it). v0.5.1 (B3): an error after `started` first prints `status:"failed"` with `pre_tokens` and a short `reason` (`summary_failed`, `cancelled`, `source_changed`, `over_budget`, `empty_summary`, `error`; never text, summary or secrets), then fails as before. These lines carry **no `session_id`**, so Studio never records them as native identity; run-manager turns them into the existing `compression.*` events and the chat shows the Hermes compression row (v0.4.6). v0.4.6 kept the estimate out of the context meter; v0.5.1 reverses that on the display side (B1, run-manager `host_compaction` handling, not this wrapper).
4. Merge the user-message ledger, archive the source transcript, then select recent inert quotations within the budget. Never replay hidden reasoning/signatures or binary image/document data as text. Tool call/results remain paired; oversized plain text is an explicitly labeled suffix excerpt.
5. Launch a successor native UUID with the summary/reference plus the real current request. Normal native stream events reach Studio; the native session-id event preserves Studio's existing resume wiring.
6. Commit the checkpoint atomically before forwarding terminal success. Every real attempt, including ordinary turns and recovery attempts, is journaled before execution. The wrapper's child shutdown deadline is shorter than Studio's 1.5-second forced-kill deadline so locks can be released.

`/compact [focus]` uses the same host checkpoint path below the automatic threshold, with tools disabled for the acknowledgement. It does not send `/compact` to an empty successor.

## Auxiliary summary (v0.5.1)

The summary policy: the summary follows 「模型 → 辅助模型 → 压缩」; auto / unset / call failure / invalid result → Claude writes it in the same turn (the v0.5.0 fork, `SUMMARY_PROMPT` unchanged).

- **Launch contract**: a managed launch (`claude-context-launch.ts`) adds `HERMES_CC_SUMMARY_URL` (`<getLoopbackBaseUrl>/api/coding-agents/claude-context/summary`) and `HERMES_CC_SUMMARY_TOKEN`. The wrapper leaves both, and every `HERMES_CC_COMPACT_*`, out of the env of **every** native child (managed calls, pass-through, interactive). That is defence in depth, not isolation: a process of the same user, the model's Bash included, can still read `/proc/<wrapper pid>/environ`. Whoever holds the token gets no more than the endpoints offer: they never read session content (they summarize only the text a request carries and return settings), and the token dies with the run. The wrapper only ever sends to `http://127.0.0.1|localhost|[::1]` over a fresh direct connection (no env proxy).
- **Token**: `coding-agents/services/claude-summary/tokens.ts`. `startCodingAgentRun` issues one random 256-bit token per managed launch when the Studio session has no live run (a live run is handed back by `start()` and keeps its own); it replaces the session's previous token and is revoked when the launch turns out native. Memory only, compared as SHA-256 digests with `timingSafeEqual`, bound to the session's profile. The endpoints reject it once the session's run has ended (idle close after 30 min, stop, relaunch); a WebUI restart forgets all tokens.
- **Auth** (both endpoints, registered before the user-auth middleware): peer `127.0.0.1`/`::1`/`::ffff:127.0.0.1` and no `X-Forwarded-For`/`Forwarded`/`X-Real-IP` (a local reverse proxy relays remote clients from loopback) → else 403; `Authorization: Bearer <token>` matching `session_id`'s current token and a live run → else 401. Of these checks the token is the boundary; the loopback/forwarding check is only an additional filter (any local process presents a loopback peer).
- **Request** `POST …/summary`: `{"session_id", "rows":[{"role":"user"|"assistant","id"?:<native message.id>,"content":<native content>}], "previous_summary":string|null, "focus":string|null, "summary_budget":n}`. `rows` is this generation's active chain cleaned by the `visible()` rules (bootstrap prefix stripped, thinking/signatures dropped, media as placeholders, tool payloads over 8KB head/tail), meta rows excluded, native compaction summaries kept. `summary_budget` = clamp(retention target × 0.1, 4K, 16K) (8K by default). `focus` is the `/compact` text, appended to the prompt as an extra requirement.
- **Server** (`claude-summary/index.ts`, through the Studio facade `studio/public/context-compression.ts`): `resolveCompressionModelContext` (auto/unset/model missing → `{"ok":false,"reason":"unavailable"}` immediately, no deadline), records → `ChatMessage` (`claude-summary/transcript.ts`: rows of one `message.id` merge, `tool_use` → `tool_calls`, `tool_result` → `role:"tool"` with its call's name, errors prefixed `[tool error]`), then every text, tool argument, the previous summary and the focus go through `sanitizeCodingAgentTerminalOutput` (Bearer tokens, `sk-…` keys, `api_key=…` redacted) before anything leaves for the auxiliary provider; chunks of max(30K, summary-model window × 0.5) tokens; a history that already fits the summary budget can avoid redundant exact per-message counting, `buildFullPrompt`/`buildIncrementalPrompt`, `callSummarizer` → bridge `chat` with `auxiliary.compression.reasoning_effort` as `reasoning_effort` when set (like Hermes' `auxiliary.<task>.reasoning_effort`, also when the provider is auto), on a bridge worker of its own per request (so a retry after a cancel never queues behind the orphaned call), `assertUsableSummary`. Deadline = max(270s, `auxiliary.compression.timeout` × 1000) for the whole summary.
- **Response**: once accepted, headers are flushed at once with `X-Hermes-Summary-Deadline-Ms` (deadline + 15s) so the wrapper waits exactly that long (30s before headers); then `{"ok":true,"summary","model","provider","seconds","chunks"}` or `{"ok":false,"reason":"empty"|"invalid_summary"|"failed"|"timeout"|"cancelled"}`. Other statuses: 400 `bad_request`, 401 `unauthorized`, 403 `forbidden`, 413 from the 20MB body limit.
- **Fallback codes** (wrapper, `completed.reason` and `retention.summaryFallback`): `native_summary`, `aux_unconfigured` (no/non-loopback URL or token: older launch), `aux_<server reason>`, `aux_http_<status>`, `aux_timeout`, `aux_error` (transport), `aux_invalid` (non-JSON, empty or >256KiB summary). A user cancel aborts the HTTP request (the server starts no further chunk; an in-flight bridge call is left to finish and discarded) and the turn fails as `cancelled`.
- **Only new history**: `checkpoint.summary` (and `pending.summary`) keeps the last summary text; the next compaction sends it as `previous_summary` plus only this generation's rows. A v0.5.0 checkpoint has no such field: the wrapper recovers the summary from this generation's bootstrap prefix (between `=== [2/4] SUMMARY OF THE CONVERSATION SO FAR ===` and `=== [3/4]`), accepting it only when it matches the recorded `retention.summaryHash`; when it cannot, the rows are sent with the prefix kept, so nothing is lost.
- **Emergency switch**: an empty `<WebUI home>/coding-agent/claude-context/NATIVE_SUMMARY` sends every summary back to Claude immediately, no rebuild. `DISABLED` keeps its meaning (whole wrapper off).

## Compression settings (v0.5.1)

Agent 管理 → Claude → 压缩设置 (`claude-compression-settings.ts`, `resolveClaudeCompressionSettings`) → env `HERMES_CC_COMPACT_ENABLED` (`1`/`0`), `…_THRESHOLD`, `…_TARGET_RATIO`, `…_PROTECT_LAST_N`, `…_PROTECT_FIRST_N` (names mirrored in `bin/claude-context/policy.mjs`; a test checks they match). A Studio run, and so its launch env, lives across turns, so the wrapper also asks `POST …/settings` (same auth, body `{"session_id"}`, answer `{"ok":true,"env":{…}}`, 2s timeout) at the start of every managed turn: a settings change applies to the next message. Endpoint failure → the launch env; missing or non-numeric values → the defaults 0.4 / 0.08 / 20 / 3 / enabled; out-of-range values clamp to the Hermes ranges.

| Derived value | Rule | Default (0.4 / 0.08 / 20 / 3) | Follow main 0.8 / 0.5 |
|---|---|---|---|
| Trigger | 1M × min(threshold, 0.8) | 400,000 (= v0.5.0) | 800,000 |
| Retention target | min(1M × target_ratio, trigger × 0.8) | 80,000 (= v0.5.0) | 500,000 |
| Hard limit (`selectHistory`) | trigger × 0.9 | 360,000 (v0.5.0: 200,000) | 720,000 |
| Protected-tail growth cap (`protectLimit`) | max(retain, trigger × 0.5) | 200,000 | 500,000 |
| Skip the `/context` fork | fresh native usage < trigger − 20,000 | < 380,000 (= v0.5.0) | < 780,000 |
| Native backstop `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | min(1M, max(600K, trigger + 200K)) | 600,000 (= v0.5.0) | 1,000,000 |
| Summary budget | clamp(target × 0.1, 4K, 16K) | 8,000 | 16,000 |

With the defaults, the trigger, retention target, `/context` skip and native backstop equal v0.5.0, and the Claude fork keeps its v0.5.0 summary prompt (the 8K summary budget belongs to the new auxiliary path). New are two floors, the newest 20 records and the first 3 records kept verbatim (the recent floor may grow retention up to half the trigger), and the hard limit (200K → trigger × 0.9), so the retained successor can differ from v0.5.0's.

`enabled=0` stops threshold compaction (no `/context` fork either); manual `/compact` still compacts and the native backstop stays on.

## Multiple native results

A background task notification (e.g. an Agent tool call with `run_in_background`) starts another native turn inside the same `-p` process, and each turn ends with its own `result` (real CLI: `STARTED`, then the task report, exit 0). A call succeeds when the process exits 0 and every result is a success; only the final result is forwarded because Studio completes the turn on the first result it receives. v0.4.0 and earlier required exactly one result and failed such turns with exit 75.

## Persistent state

Shared ownership/lock root: `<WebUI home>/coding-agent/claude-context`.

Each private scope is keyed by profile, Studio session, native configuration/project root and workspace. Scope directories use mode 0700; files use 0600. `checkpoint.json` records current/known native UUIDs, generation, bootstrap identity, retention estimates (v0.5.1 also `summarizer`, `summaryModel` or `summaryFallback`) and observed single-call usage; v0.5.1 adds only optional fields, `summary` and `firstRecords` (also in `pending.json`), so older checkpoints resume unchanged. `pending.json` records every attempted input identity. Native ownership prevents two Studio/profile scopes from silently reusing the same native UUID.

Input counts include `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`. `result.usage` can be an entire run's cumulative billing usage and is never used as a current-context snapshot. Billing ledger and the existing UI usage display are not redefined by this feature.

## Failure and recovery

- Summary/validation failures do not publish a successor checkpoint or terminal success. Source native history remains available.
- A started candidate may have executed tools even if no successful result was received. Never automatically replay an old attempt or assume absence of a transcript means absence of effects.
- Studio enables explicit candidate continuation for the next **different** user instruction (`HERMES_CC_RECOVER_PENDING=resume`); repeating any failed attempt's exact input is blocked. Native `--resume` must name that candidate.
- Missing-transcript or deliberately abandoned candidates require operator inspection. The wrapper's administrative abandon requires all three exact bindings: `HERMES_CC_ABANDON_PENDING=<candidate UUID>`, `HERMES_CC_ABANDON_SOURCE=<source UUID>`, and `--resume <source UUID>`, with the same scope environment. It archives the pending record, preserves ownership, blocks old input hashes, and executes no stdin request. It **does not undo external effects**. Never inject these flags into a normal chat launch.
- SIGKILL/container crash may leave locks; inspect the recorded PID and pending journal before removing a stale lock. Do not blindly unlink locks or discard pending state to make a retry succeed.

## Code and tests

- `bin/claude-context/*.mjs`: native CLI wrapper, private policy overlay and compression settings (`policy.mjs`), history selection/ledger/summary records (`core.mjs`), WebUI endpoint client (`summary.mjs`, v0.5.1), model capability rule (`models.mjs`, mirrored in `claude-context-launch.ts`), PreCompact hook, process/signal and checkpoint handling.
- `packages/server/src/modules/coding-agents/services/claude-context-launch.ts`: scope/platform/model/policy-preserving launch adapter (v0.5.1: summary endpoint + token, compression env).
- `coding-agents/services/claude-summary/` (v0.5.1): tokens, native records → `ChatMessage`, summary/settings handlers; routes `routes/claude-context.ts`; Studio facade `studio/public/context-compression.ts`.
- `services/index.ts` `startCodingAgentRun`: chat-only integration and token issue. No frontend restructuring or database migration.
- `npm run test:claude-context`: Node protocol/filesystem/process regression tests; included in Docker build.
- Focused Vitest: `claude-context-launch`, `coding-agents-launch`, `coding-agent-resume-config`, `coding-agent-run-manager-windows`, `coding-agent-session-command`; v0.5.1 `claude-summary` (auth, conversion, availability, reasoning effort) and `claude-summary-wrapper` (real wrapper ↔ real route).
- Test fixtures are synthetic; mocked protocol tests must not be presented as real model acceptance results.

## Release boundary

Run the focused tests, type checks, application build and continuity patch verification before releasing. Validate the Docker image in an isolated installation before updating an existing installation. A successful source build is not evidence that an already-running container has been updated.
